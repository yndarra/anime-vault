anime-vault — сбор картинок с досок для anime-sort
==================================================

Окно (anime-vault.exe из релиза; из исходников — anime-vault.vbs или ярлык anime-vault в коллекции; CustomTkinter):
    Обзор — сколько ждёт раскладки, папки dataN, файлы на досках, дубли на просмотр, последняя раскладка;
    Скачать — что сделать перед началом и живой индикатор «браузер открыт / закрыт», запуск;
    Разложить — источники и прикидка, сколько выйдет папок dataN, запуск (скрыта, если раскладка выключена);
    Дубли — что раскладка убрала в duplicates: миниатюра рядом с оригиналом, «В Корзину» по одному или все сразу;
    Настройки — язык (русский / English), папка коллекции, раскладка вкл/выкл и размер пачки, вход на сайт
    (куки браузера или файл cookies.txt), доски — просто ссылками.
    Внизу — журнал команды; её вопросы («Перенести?», «Готово?») — кнопками. Окно запускает те же команды,
    что и .bat-файлы (вопросы идут служебной строкой при ANIME_VAULT_GUI=1 — anime_vault\console.py).

Две команды:
    download     скачать НОВОЕ с досок (Pinterest или любой сайт gallery-dl: Danbooru, Pixiv, X …)
    distribute   разложить новое (скачанное + Anime ADD\processed_data) по папкам dataN по 500 файлов
Дальше папки dataN сортирует anime-sort (https://github.com/yndarra/anime-sort).

Код, настройки (config.json), кэш хэшей (cache\) и журналы (logs\) лежат здесь, в проекте (у .exe — рядом с ним);
в папке с картинками — только манифест anime-paths.json и маленькие .bat-файлы.


Папка коллекции (Pictures\Anime)
--------------------------------
anime-paths.json            манифест: пути коллекции (относительно этой папки) и пути к проектам.
                            Нужен для связки с anime-sort; без него пачки — <коллекция>\dataN,
                            источники раскладки — папки досок (кроме «только хранить»)
distribute.bat        раскладка нового по dataN
data\
    Anime JSON Pinterest\data\
        download.bat                  скачивание новых пинов
        01. An i me\, 02. Шедевры\    скачанные доски — все фото прямо в папке доски, без разделов;
                                      «02. Шедевры» — «только хранить» (keep): обновляется с Pinterest, но не раскладывается
        .gallery-dl-archive.sqlite3   что уже скачано (не удалять — иначе всё будет проверяться заново)
        .download-work\               временные файлы скачивания (можно удалить, когда ничего не качается)
    Anime ADD\
        data\                         необработанное (скриншоты, сохранёнки не с Pinterest)
        processed_data\               то же после ручной обработки — отсюда distribute забирает в dataN
dataN\data1, data2 …  пачки для anime-sort
test-dataN\           наборы, обработанные anime-sort
Waifu\                итог anime-sort
duplicates\           дубли, найденные distribute (страница «Дубли» в окне)


Папка проекта (служебное — не в git)
------------------------------------
config.json           личные настройки (их пишет страница «Настройки»): язык, папка коллекции, раскладка и
                      размер пачки, доски (name — папка, slug + user — доска Pinterest, или url — любой сайт;
                      keep — «только хранить»), вход (browser_cookies: «opera:<профиль>», «firefox», путь к
                      cookies.txt или пусто). Образец — config.example.json
cache\hashes.json     кэш хэшей: что уже есть в коллекции (чтобы не считать SHA-1 заново)
logs\                 журналы distribute_<время>.json: что куда перенесено и пары «дубль → оригинал»


download — скачивание
---------------------
1. Окно покажет короткую инструкцию под выбранный способ входа: для Opera / Chrome / Edge … — войти на сайт и
   ПОЛНОСТЬЮ закрыть браузер (у открытого браузера на Chromium куки заблокированы); Firefox и файл cookies.txt
   закрывать не нужно. Новые Chrome и Edge шифруют куки так, что их не прочитать, — для них файл cookies.txt.
2. Всё, что уже есть в любой dataN, в «01. An i me» или в Anime ADD\processed_data (то есть в dataN и
   в источниках раскладки), добавляется в архив gallery-dl — это не качается. Пины узнаются по имени файла
   (pinterest_<id> — id бывает и числом, и буквами), файлы других сайтов — по <сайт>_<id>. Шедевры качают своё
   как обычно: что уже в них, помнит сам архив gallery-dl.
3. Каждый новый файл: картинка + текст (заголовок и описание пина, у Danbooru-подобных — теги персонажей и тайтла
   вшиваются в jpg/png — их читает anime-sort) → в папку своей доски. Окно пишет, сколько скачано, и объясняет
   ошибки (403 — не выполнен вход, куки заблокированы — браузер открыт, 429 — подождать, и т. д.).
Прервали или сбой — запустите снова: продолжит с места остановки.

distribute — раскладка
----------------------
Ищет новое в sources (anime-paths.json; доски «только хранить» — Шедевры — заблокированы, даже если указаны),
отбрасывает дубли (тот же пин или та же картинка уже в dataN/test-dataN),
показывает план («data82: 500, data83: 500, data84: 213») и после подтверждения ПЕРЕНОСИТ файлы.
Номера идут после самого большого dataN; последняя папка может быть меньше 500 — следующий запуск
её не дополняет, а начинает новую. Дубли уходят в duplicates\<время>, в журнал — где лежит их оригинал.
Откуда дубли, если скачивание и так пропускает известное: одна и та же картинка под разными пинами,
одинаковые скриншоты в processed_data, файл, скопированный в два источника.

Консольные окна (.bat)
----------------------
Цветной журнал; ошибка — красным с подсказкой «Что сделать»; окно не закрывается само — в конце ждёт Enter.

Установка
---------
Проще всего — anime-vault-windows.zip из Releases на GitHub: распаковать и запустить anime-vault.exe.
Из исходников (один раз):
    cd <папка проекта anime-vault>
    py -3.12 -m venv venv
    venv\Scripts\pip install -r requirements.txt
Манифест (для anime-sort): скопировать anime-paths.example.json в папку коллекции под именем anime-paths.json.
Настройки: в окне, страница «Настройки» (или вручную — по образцу config.example.json).
.bat-файлы: копии launchers\anime-vault.bat под именами команд (download.bat, distribute.bat) — команда
берётся из имени файла, корень коллекции — ближайшая папка вверх с anime-paths.json, путь к проекту — "project".
Сборка .exe: venv\Scripts\pip install pyinstaller, затем venv\Scripts\python packaging\build.py.
Релиз: тег v* (git tag v1.1.0, git push origin v1.1.0) — GitHub сам соберёт .exe и выложит архив.

Код
---
anime_vault\__main__.py    python -m anime_vault [download|distribute] [--root <папка коллекции>]; без команды — окно
anime_vault\paths.py       где config.json, cache\, logs\ (у .exe — рядом с ним)
anime_vault\manifest.py    чтение anime-paths.json и config.json, разбор ссылок на доски
anime_vault\known.py       что уже есть: пины и файлы сайтов по имени, прочее по SHA-1 (кэш cache\hashes.json)
anime_vault\browsers.py    откуда куки (браузер / cookies.txt) и открыт ли браузер
anime_vault\download.py    gallery-dl, вшивание текста, понятные ошибки
anime_vault\distribute.py  раскладка по dataN, журнал с парами «дубль → оригинал»
anime_vault\i18n.py, en.py язык окна и сообщений: строки в коде по-русски, en.py — английские переводы
anime_vault\gui\          окно: app.py (страницы), runner.py (запуск команд, вопросы), collection.py (сведения, дубли)
anime_vault\console.py     цветной вывод, ошибки «что сделать», ожидание Enter
launchers\anime-vault.bat  запускатель для папки коллекции (только ASCII: cmd читает его до смены кодировки)
packaging\build.py         сборка anime-vault.exe (PyInstaller) и архива для релиза
tests\                     проверки (pytest): раскладка, ссылки, куки, переводы
