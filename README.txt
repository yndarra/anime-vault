anime-vault — сбор аниме-картинок для anime-sort
================================================

Окно (anime-vault.vbs в папке проекта, ярлык anime-vault в коллекции; CustomTkinter, anime_vault\gui):
    Обзор — сколько ждёт раскладки, папки dataN, файлы на досках, дубли на просмотр, последняя раскладка;
    Скачать — что сделать перед началом и живой индикатор «Opera GX открыта / закрыта», запуск;
    Разложить — источники и прикидка, сколько выйдет папок dataN, запуск;
    Настройки — config.json (папка коллекции, размер пачки, пользователь Pinterest, профиль браузера, доски).
    Внизу — журнал команды; её вопросы («Перенести?», «Готово?») — кнопками. Окно запускает те же команды,
    что и .bat-файлы (вопросы идут служебной строкой при ANIME_VAULT_GUI=1 — anime_vault\console.py).

Две команды:
    download     скачать НОВЫЕ пины с досок Pinterest (gallery-dl, вход через куки браузера)
    distribute   разложить новое (скачанное + Anime ADD\processed_data) по папкам dataN по 500 файлов
Дальше папки dataN сортирует anime-sort (https://github.com/yndarra/anime-sort).

Код, настройки скачивания (config.json), кэш хэшей (cache\) и журналы (logs\) лежат здесь, в проекте;
в папке с картинками — только манифест anime-paths.json и маленькие .bat-файлы.


Папка коллекции (Pictures\Anime)
--------------------------------
anime-paths.json            манифест: пути коллекции (относительно этой папки) и пути к проектам
distribute.bat        раскладка нового по dataN
data\
    Anime JSON Pinterest\data\
        download.bat                  скачивание новых пинов
        01. An i me\, 02. Шедевры\    скачанные доски — все фото прямо в папке доски, без разделов;
                                      «02. Шедевры» — «только хранить» (keep): обновляется с Pinterest, но не раскладывается
        .gallery-dl-archive.sqlite3   что уже скачано (не удалять — иначе всё будет проверяться заново)
        .download-work\               временные файлы скачивания (можно удалить, когда ничего не качается)
    Anime ADD\
        data\                         необработанное (скриншоты, сохранёнки не с Pinterest)
        processed_data\               то же после ручной обработки — отсюда distribute забирает в dataN
dataN\data1, data2 …  пачки для anime-sort
test-dataN\           наборы, обработанные anime-sort
Waifu\                итог anime-sort
duplicates\           дубли, найденные distribute (посмотреть и удалить вручную)


Папка проекта (служебное — не в git)
------------------------------------
config.json           личные настройки: размер пачки (batch_size) и доски Pinterest (пользователь, доски, профиль
                      браузера для куки). Образец — config.example.json
cache\hashes.json     кэш хэшей: что уже есть в коллекции (чтобы не считать SHA-1 заново)
logs\                 журналы distribute_<время>.json (что куда перенесено)


download — скачивание
---------------------
1. Окно покажет короткую инструкцию: войти в Pinterest в Opera GX, ПОЛНОСТЬЮ закрыть браузер, нажать Enter
   (доски приватные — gallery-dl берёт куки из браузера, а у открытого браузера они заблокированы).
2. Пины, которые уже есть в любой dataN, в «01. An i me» или в Anime ADD\processed_data (то есть в dataN и
   в источниках раскладки), добавляются в архив gallery-dl — такие пины не качаются. Шедевры качают своё как
   обычно: что уже в них, помнит сам архив gallery-dl.
3. Каждый новый пин: картинка + текст пина (заголовок и описание вшиваются в jpg/png — их читает anime-sort)
   → в папку своей доски. Окно пишет, сколько скачано, и объясняет ошибки (403 — не выполнен вход,
   куки заблокированы — браузер открыт, 429 — подождать, и т. д.).
Прервали или сбой — запустите снова: продолжит с места остановки.

distribute — раскладка
----------------------
Ищет новое в sources (anime-paths.json; доски «только хранить» — Шедевры — заблокированы, даже если указаны),
отбрасывает дубли (тот же пин или та же картинка уже в dataN/test-dataN),
показывает план («data82: 500, data83: 500, data84: 213») и после подтверждения ПЕРЕНОСИТ файлы.
Номера идут после самого большого dataN; последняя папка может быть меньше 500 — следующий запуск
её не дополняет, а начинает новую. Дубли уходят в duplicates\<время>.

Окна
----
Цветной журнал; ошибка — красным с подсказкой «Что сделать»; окно не закрывается само — в конце ждёт Enter.

Установка (один раз)
--------------------
    cd <папка проекта anime-vault>
    py -3.12 -m venv venv
    venv\Scripts\pip install -r requirements.txt
Манифест: скопировать anime-paths.example.json в папку коллекции под именем anime-paths.json и поправить пути.
Настройки: скопировать config.example.json в config.json (здесь, в проекте) и вписать свои доски Pinterest.
.bat-файлы: копии launchers\anime-vault.bat под именами команд (download.bat, distribute.bat) — команда
берётся из имени файла, корень коллекции — ближайшая папка вверх с anime-paths.json, путь к проекту — "project".

Код
---
anime_vault\__main__.py    python -m anime_vault <download|distribute> [--root <папка коллекции>]
anime_vault\manifest.py    чтение anime-paths.json (коллекция) и config.json (проект)
anime_vault\known.py       что уже есть: пины по имени файла, прочее по SHA-1 (кэш cache\hashes.json)
anime_vault\download.py    gallery-dl, вшивание текста пина, понятные ошибки
anime_vault\distribute.py  раскладка по dataN
anime_vault\gui\          окно: app.py (страницы), runner.py (запуск команд, вопросы), collection.py (сведения)
anime_vault\console.py     цветной вывод, ошибки «что сделать», ожидание Enter
launchers\anime-vault.bat  запускатель для папки коллекции (только ASCII: cmd читает его до смены кодировки)
tests\test_core.py         проверки (pytest): раскладка на временной коллекции, доски «только хранить», разбор вывода
